# DSP 在线调试环境 · 踩坑与排查

> 本文件只收录**踩过的坑、事故经过、排查方法**。日常怎么用见
> [`在线调试环境-使用说明.md`](使用说明.md)。
>
> **固定组合：`BepInEx 5.4.17 + Doorstop 3.4.0`**。任何"升级 BepInEx / 换 Doorstop"的念头都先读 §1。
> 之所以锁死这个组合：最终 MOD 要上传 R2（Thunderstore），玩家侧运行时就是 `xiaoye97-BepInEx 5.4.17`，
> 本机必须同代验证，否则会"本机好好的、上传后玩家那边不加载"。

## 1. 加载器与 BepInEx 版本（最高频的坑）

### 1.1 Doorstop 有两代，配置格式不同，混装会静默失败

| | Doorstop 3.4.0（**本环境采用**） | Doorstop 4.5.0（已弃用） |
|---|---|---|
| `winhttp.dll` | 25,088 B | 26,112 B |
| `doorstop_config.ini` | 891 B，段 `[UnityDoorstop]`，键 `targetAssembly` | 1460 B，段 `[General]` / `[UnityMono]`，键 `target_assembly` |
| `.doorstop_version` | **不存在**（Doorstop 3 不生成） | 存在，内容 `4.5.0` |
| 附带文件 | `changelog.txt` 247 B | `changelog.txt` |
| 适配的 BepInEx | **5.4.17** | 5.4.23.x |
| 与 R2/Thunderstore | **一致**（社区在架包） | 不一致 |

**症状**：游戏照常启动，但 `BepInEx\LogOutput.log` 不更新（还是上一轮内容），日志里没有 `[DspBridge]` 行，
`dev-loop -Mode up` 等满超时后报 `FAIL: the game process is running but the bridge did not become ready`，
MCP/HTTP 全连不上。**没有任何报错**。

**原因**：注入器、`doorstop_config.ini`、`BepInEx\core` 三者来自不同代际，加载器找不到它认识的目标就静默放弃。

**处理**（一条命令恢复，自动备份到 `_backup_dsp_bridge_<时间戳>\`）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-game-side.ps1
```

**验证**（本机没有 `doctor`，用这 4 条手工确认；命令在工具包根
`<repo>\` 下执行）：

```powershell
$g = '<game>'
# 1) 日志第一行必须是 BepInEx 5.4.17.0 - DSPGAME
Get-Content "$g\BepInEx\LogOutput.log" -TotalCount 2
# 2) 日志里应有 [DspBridge] 配置就绪 / 已监听 http://127.0.0.1:17890/
# 3) 加载器三件套是 Doorstop 3 代，且没有 .doorstop_version
(Get-Item "$g\winhttp.dll").Length                  # 25088
(Get-Item "$g\doorstop_config.ini").Length          # 891
Test-Path "$g\.doorstop_version"                    # 必须是 False
# 4) runtime.json 应存在且 pid 与游戏进程一致
Get-Content "$env:LOCALAPPDATA\DSPBridge\runtime.json"
```

### 1.2 实测：Doorstop 4.5.0 驱动不了 BepInEx 5.4.17

2026-10-24 尝试"只降 BepInEx、Doorstop 保持 4.5.0"：游戏起得来，但 232 秒内 `LogOutput.log` 完全没被重写，
桥接没注入，进程最终退出。**结论：加载器 + 配置 + core 必须整套同代，不能只换一半。**

### 1.3 本机三次加载器事故（都表现为"没注入、没报错"）

| 时间 | 当时状态 | 经过 | 处理 |
|---|---|---|---|
| 10/17 | 原始 Doorstop 3.4.0 | 按旧文档装了 Doorstop 4.5.0 + 5.4.23.5（为配开发指南） | 桥能用，但偏离 R2 基线 |
| 10/22 | 被外部工具改回 Doorstop 3.4.0 + core 5.4.17 | r2modman 的 mod 部署覆盖了游戏根目录，桥接消失；`.doorstop_version` 残留 4.5.0 | 当时重装 Doorstop 4 |
| 10/25 | 混代（`[General]` + 3.4.0 注入器） | 决定改回 R2 基线 | `install-game-side.ps1` 装 3.4.0+5.4.17，已删除残留 `.doorstop_version` |

**混代识别三件套**：`winhttp.dll` 大小（25088 vs 26112）、`doorstop_config.ini` 里的段名
（`[UnityDoorstop]` vs `[General]/[UnityMono]`）、`.doorstop_version` 是否存在。
本机 `install-game-side.ps1` 会做这三项校验并拒绝一半新一半旧的状态。

### 1.4 插件编译版本与运行时版本

- 插件引用 `tools\bepinex-lib\BepInEx.dll`（当前 **5.4.17.0**，116,224 B）与
  `tools\refs\Assembly-CSharp.dll`（取自游戏版本）。
- `tools\bepinex-lib` 在 10/25 已从 5.4.23.5 换回 5.4.17（旧快照在
  备份目录（自行保留））。
- BepInEx/0Harmony 不是强名称程序集，编译进某一版也能在另一版运行时加载，**但不要靠这个兼容**：
  出现过增量构建沿用 5.4.23.5 AssemblyRef、产物哈希对不上的混淆。统一 5.4.17 后消失。
- 换 `tools\bepinex-lib` 版本后必须删 `DspBridge\bin`/`obj` 再构建，否则沿用旧引用（§4.7）。

## 2. 启动方式

### 2.1 r2modman 的 Start modded 会覆盖游戏目录（桥接消失）

本机 r2modman 在 `<r2modman>`，profile 在
`%APPDATA%\r2modmanPlus-local\DysonSphereProgram\profiles\Default\`。
反编译 `resources\app.asar` 得到的调用链：

```
launchGame(MODDED) -> setGameDirIfUnset -> throwIfNoGameDir
                   -> linkProfileFiles(game, profile)   // 把 profile 文件链接/复制进游戏目录
                   -> openGameRunningModal -> launch(...)
```

即：**点 Start modded 等于用 profile 内容重写游戏目录**，`winhttp.dll` / `BepInEx\core` /
`BepInEx\plugins` 都会被 profile 的版本替换；profile 里没有 `DspBridge` 插件，桥接就没了。
Vanilla 启动不链接，但也不带 mod。

**本机现状（2026-11-10 实测）**：profile 里是 `BepInEx 5.4.17 + Doorstop 3.4.0`（与我们的 payload 同代），
Start modded 不会再搞坏加载器，但会**用 profile 的 `BepInEx\plugins` 覆盖游戏目录** ——
只装在游戏目录的 `DspBridge.dll` 因此消失。11/10 实际发生：用 Start modded 启动后
`LogOutput.log` 里没有 `[DspBridge]`、`%LOCALAPPDATA%\DSPBridge\runtime.json` 不存在、
游戏插件列表里也没有 DspBridge（只剩 Thunderstore 那批插件）。

**正确做法**：DspBridge 必须装进 **profile**（不是只装游戏目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-r2modman-profile.ps1
```

脚本会：把 `game-side-patch\BepInEx\plugins\DspBridge.dll` 写进
`%APPDATA%\r2modmanPlus-local\DysonSphereProgram\profiles\<Profile>\BepInEx\plugins\DspBridge\`；
统一写 `icarus-ii.cfg`（`DebugToolConsole=true` / `PermissionLevel=takeover`）；镜像到游戏目录；
备份到 `<profile>\_backup_dspbridge_<时间戳>\`。装完 Start modded 启动也有桥接。
（`dev-loop.ps1` 走 Steam 只读游戏目录，所以两处都装才覆盖两种启动方式。）

### 2.2 Electron 程序（r2modman）从本环境启动会"秒退"

本会话环境带 `ELECTRON_RUN_AS_NODE=1`，Electron 应用继承后当 Node 运行，无脚本即 exit 0、不出窗口。
处理：启动前先 `Remove-Item Env:ELECTRON_RUN_AS_NODE` 再 `Start-Process`。

### 2.3 从工具调用里启动的 GUI 进程会被"进程树清理"杀掉

在一次性 PowerShell 调用里 `Start-Process` 起的窗口，调用结束时随进程树一起结束（下一次调用就看不到窗口）。
处理：用后台常驻任务（`run_in_background` 的 holder：清 env → Start-Process → 长 sleep）保活，
其余调用负责截图/点击；收尾时 kill 掉 holder。

### 2.4 Steam 侧

- 必须 Steam 版、AppID `1366540`；`dev-loop` 用 `steam.exe -applaunch 1366540`（注册表：
  `HKCU:\SOFTWARE\Valve\Steam\SteamExe`）。
- 游戏已在运行时会先 `game stopped` 再开；Steam 没登录/离线时 `-Mode up` 会失败。
- Steam 校验完整性/更新游戏后，`BepInEx\core` 可能被还原成旧版、注入器可能被换——重跑 `install-game-side.ps1`。

## 3. 存档与游戏状态

### 3.1 载入缺 mod 的旧存档 → 崩溃退游戏

现象：点"继续"后约 10 秒内 `gameLoaded` 仍 false、随后 HTTP 连接被拒、游戏进程消失。
日志里 `DSP Mod Save Pre Load` 读到未安装 mod（例：`dsp.common-api.CommonAPI`、
`Gnimaerd.DSP.plugin.MoreMegaStructure`、`com.ckcz123.DSP_Battle`、`org.ProfessorCat305.OrbitalRing` 等）的数据，
ErrorAnalyzer 打印 DSPModSave 栈，最后 `[DspBridge] 已停止 HTTP 监听（OnApplicationQuit）`。

**结论**：调试验证停在主菜单即可（`gameLoaded=false` 时 `verify-live` 会跳过存档内检查并打 NOTE）；
需要存档态验证时，用与存档 mod 集合一致的 profile。

### 3.2 主菜单态的行为

- `/state` 里没有行星/存档数据；`get_power`/`get_planet_power`/`list_planets` 等依赖存档的 op 返回空/不可用。
- `set_pause` 在菜单态 `isPaused` 会保持 `false`（暂停状态由游戏内 `GameMain` 决定），属预期。

### 3.3 改配置必须重启游戏

`AllowWrites`、`Port`、`Token`、`SnapshotEveryFrames` 都在插件启动时读入；BepInEx 5.4.17 不热重载 cfg。
`dev-loop -Mode restart -Writes on/off` 会先改 cfg 再重启，就是为这个；用完务必恢复 `off`。

### 3.4 模组兼容性（本机装了 QSystem 等）

游戏目录下 `BepInEx\plugins` 里有 `DSPQualitySystem` 等第三方插件。切到 5.4.17 后实测它们仍能加载
（日志 `Harmony PatchAll OK`），但要注意：**改 Harmony 代码必须重启游戏**，热重载不生效。

## 4. PowerShell 与工具脚本

### 4.1 `tools\*.ps1` 必须纯 ASCII（PS 5.1 按 ANSI 读脚本）

**现象**：脚本里的中文路径变乱码（报错显示 `寮€鍙戞枃妗?`），GDI+ 保存图片报
`A generic error occurred in GDI+`。

**处理**：PowerShell 脚本一律只写 ASCII（中文只放 md/日志）；需要中文路径的辅助脚本放纯 ASCII 目录
（例：`<workspace>\_tmp\`）。修改后用 `$bytes -gt 127` 扫一遍确认 non-ASCII = 0。

### 4.2 用 PS 5.1 读写含中文的文件会破坏内容

- `[xml](Get-Content $csproj -Raw)` 读 UTF-8 无 BOM 的 csproj（含中文注释）会 XML 解析失败：
  `“<”(十六进制值 0x3C)是无效的特性字符` → 加 `-Encoding UTF8`。
- `Get-Content -Raw` + `Set-Content -Encoding UTF8` 往返写 md/csproj：中文变乱码、`Text="..."` 引号被吞，
  MSBuild 报 `error MSB4025`。**处理**：文本文件一律用编辑工具（edit/write）改，不要用 Set-Content 往返。

### 4.3 `Split-Path` 不能重复传 `-Parent`

`Split-Path $p -Parent -Parent -Parent` 报
`Cannot bind parameter because parameter 'Parent' is specified more than once`。
正确：`Split-Path (Split-Path $d -Parent) -Parent`。（`build-and-deploy.ps1` 与 `dev-loop.ps1` 的历史 bug 都是它。）

### 4.4 `dspenv.ps1` 会重定向环境变量

`tools\dspenv.ps1` 把 `DOTNET_ROOT/CLI_HOME/NUGET_PACKAGES/TMP/TEMP/APPDATA/LOCALAPPDATA`
全部重定向进 `tools\`（便携化）。因此：

- 需要"真实"路径时必须在 dot-source 之前取，例如
  `[Environment]::GetFolderPath([Environment+SpecialFolder]::LocalApplicationData)`。
- 直接 `dotnet build` 前必须 dot-source `tools\dspenv.ps1`，否则 SDK 首次运行要写 `%APPDATA%`。
- 用变量路径 dot-source 会被安全策略拦截（`Rule: analysis.dynamic-shell-source`）；用字面量路径。

### 4.5 插件源码的编码：UTF-8 无 BOM → csc 按 ANSI 读 → 日志中文乱码

**现象**：日志里 `[DspBridge] 配置就绪` 变成 `[DspBridge] 閰嶇疆灏辩华`，但插件功能正常。
**原因**：`DspBridge\*.cs` 是 UTF-8 无 BOM，`csc` 默认按系统 ANSI(GBK) 解码源码里的中文字符串。
**修复**：`DspBridge.csproj` 已加 `<CodePage>65001</CodePage>`（同时 `-codepage:65001` 也可）。
注意：**日志文件本身是 UTF-8 的**；PS 里 `Get-Content` 用 ANSI 解码会显示乱码，那是显示问题，
用 UTF-8 方式读（`[IO.File]::ReadAllLines($p,[Text.Encoding]::UTF8)`）就能看到正常中文。

### 4.6 套件结果看输出标记，不看 exit code

带重定向 stdio 的 .NET 子进程会让外层 PS 报 stray 非零退出码（2026-10-17 复现：只有 `exit 0` 的脚本返回 0，
加了 .NET 子进程后返回 2）。`test-all.ps1` 因此按子进程输出里的标记判定（`ALL ... PASSED`），
不要只看 `$LASTEXITCODE`。手工跑 `powershell -File` 时同理，先看最后一行标记。

### 4.7 执行策略

本机 `Get-ExecutionPolicy -Scope CurrentUser` = `Restricted`。所有脚本调用统一带
`-NoProfile -ExecutionPolicy Bypass -File`，否则 `cannot be loaded because running scripts is disabled`。

### 4.8 `build-and-deploy.ps1` 的两个历史 bug（已修）

1. `[xml]$projectXml = Get-Content $Project -Raw` 未指定 `-Encoding UTF8` → 中文注释使 XML 解析失败 →
   TargetFramework 读空 → 判定 "not an in-game plugin"、`DeployDir=SKIP`，**静默不部署**。
2. `Split-Path $DeployDir -Parent -Parent -Parent` → 参数重复报错。

---

### 4.9 `-File` 传 JSON 参数会被吞掉引号

`powershell -File tools\icarus-ctl.ps1 -ArgsJson '{"latitude":0}'` 到子进程后变成 `{latitude:0}`，
工具收到 `invalid_args`。**处理**：JSON 写进文件，用 `-ArgsFile path`（`icarus-ctl.ps1` 已支持），
或用 `--%` 停止解析、或把脚本内部写死参数。

## 5. 运行时 / HTTP / MCP

### 5.1 `runtime.json` 残留会让工具误判"游戏在跑"

旧版插件（1.0.0）退出时不删 `%LOCALAPPDATA%\DSPBridge\runtime.json`，工具/MCP 会找到已死端口。
本机实际复现过：游戏 13:40:46 干净退出，runtime.json 仍留着 pid 12052 的旧内容。
**已修（1.0.1）**：`OnApplicationQuit` 里校验 runtime.json 里的 pid 且不是自己托管的预加载进程，才删除。

判断是否 stale：文件里的 `pid` 与当前 `DSPGAME` 进程对不上，或 `/health` 连不上。
处理：先 `-Mode down`，或手动删 runtime.json 再 `-Mode up`。
边界：pid 会被系统复用，极端情况下旧文件里的 pid 恰好等于新进程 pid —— 忽略这种小概率。

### 5.2 401 / token

- 请求必须带 `Authorization: Bearer <runtime.json.token>`，否则 `401`。
- token 在 runtime.json 与 `BepInEx\config\org.yourname.dspbridge.cfg` 的 `Token` 里；
  验证脚本会断言 token **不回显**到工具输出/模型上下文。
- runtime.json 可能被 `dspenv` 重定向到 `tools\localappdata\DSPBridge\runtime.json`
  （工具链已兼容多候选路径：env `DSP_BRIDGE_RUNTIME` → 真实 LocalAppData → USERPROFILE → 副本内）。

### 5.3 端口占用

`17890` 被别的进程占 → 桥起不来，日志里 `已监听` 行缺失。用 `-Mode status` 看诊断，
或改 cfg `Port` 后 `-Mode restart`。本机**没有** `doctor` 的"活游戏占用端口"自动判定，
`-Mode status` 会显示端口占用者。

### 5.4 MCP 协议层的坑

- `McpException` 的 message 到不了模型 → 工具内部必须 `return IsError = true` 并带上错误文本。
- `[McpServerResource]` 必须写 `MimeType`。
- 无 C# 默认值的参数会被 SDK 当成**必填**；可选参数要给默认值。
- 服务器 stdout 只能输出 JSON-RPC；日志/诊断一律 stderr（`run-dsp-mcp.cmd` 已按此配置）。
- 客户端注册后要**重启客户端**；`.mcp.json` 路径失效（旧机器路径）时重跑 `setup-machine.ps1` 重写，
  或手改 `.mcp.json` / `MCP-REGISTRATION.txt` 指向 `tools\run-dsp-mcp.cmd`。

### 5.5 `-batchmode` 不能拿来截图

Unity 的 `-batchmode` 是**无图形设备**模式，不创建窗口与渲染表面，截图/鼠标都不存在。
要"后台渲染截图"只能靠：窗口化/无边框全屏下 `PrintWindow(PW_RENDERFULLCONTENT)`、桌面 `BitBlt`/`CopyFromScreen`、
或游戏内加截图插件。本机 `dev-loop -Mode shot` 用的就是 PrintWindow + 桌面回退。

### 5.6 像素级操作的三个前提

1. 进程要 `SetProcessDPIAware`，否则 200% 缩放下坐标被当虚拟像素（本机实测：非 DPI-aware 时
   `SetCursorPos(310,854)` 被钳到 `854→800`，点击落空）。
2. 窗口要前台（`-Foreground`），否则 PrintWindow 可能出黑帧、SendInput 可能进不了游戏窗口。
3. 游戏是无边框全屏（"光标受限"），没有系统标题栏，`MainWindowHandle` 仍是 `UnityWndClass`，可用。

### 5.7 `gameLoaded` 恒为 false（1.0.2 修复，直接影响 `-RequireSave` 与存档内验证）

现象：游戏已经进存档、`/state` 有数据，但 `/health` 的 `gameLoaded` 一直是 `false`；
`dev-loop -Mode up -RequireSave` 永远等不到。根因：`IsGameLoaded()` 把 `isMenuDemo` 当**静态字段**读
（`Reflect.GetStatic(GameMain, "isMenuDemo")`），而它实际是 `GameMain.instance.isMenuDemo`（实例字段）；
反射返回 null → 转型抛异常 → `catch` 吞掉 → 永远 false。
修复（1.0.2）：先取 `GameMain.instance` 再读 `isMenuDemo`，取不到时退回 `data != null`。
验证：载入存档后 5 秒内 `/health` 应变成 `"gameLoaded":true`。

### 5.8 IcarusII 通道（`127.0.0.1:8765`）常见故障

完整清单见 [`IcarusII-游戏内调试集成.md`](IcarusII-集成.md) §9，高频的几条：

- 聊天窗 / `!tool` 不工作 → 主菜单不响应聊天热键，先载入存档；再确认
  `<游戏>\BepInEx\config\icarus-ii.cfg` 里 `DebugToolConsole=true`（改完必须重启游戏）。
- `!tool` 返回 `tool_unavailable` → sidecar 没带 `--debug-tools`（由 `DebugToolConsole=true` 自动传）。
- 写工具返回 `confirmation_required` → 权限档不是 `takeover`（`limited` 只自动放行 risk≤1）。
- sidecar 无响应 / 8765 连不上 → 读 `%APPDATA%\icarus-ii\runtime.json` 的 `pid` 是否还活着；
  残留占用先结束旧进程再启动游戏。
- 401 → IcarusII token 每次 sidecar 重启都会变，重读 runtime.json；不要与 DspBridge 的 token 混用。
- 外部 WS 客户端调 `game_*` 没结果 → 这是设计如此：game 工具只由游戏内的连接执行。

## 6. 构建与产物一致性

- 插件工程已加 `<Deterministic>true</Deterministic>` + `<PathMap>$(MSBuildProjectDirectory)=/src</PathMap>`
  + `<CodePage>65001</CodePage>`，两棵源码树构建出同一哈希（当前 `DspBridge.dll` 44,032 B，1.0.2）。
- MCP server 两个副本可能是不同哈希（构建环境不同），功能一致即可。
- 换 payload/加载器后要同步两处 payload（工作区 `game-side-patch\` 与便携包同名目录）；
  本机 `install-game-side.ps1` 会校验 payload 与游戏目录的文件哈希。
- `tools\` 根目录会被 `pack-portable.ps1` 整个打包进便携包：**不要把探针脚本、日志、临时文件丢在
  `tools\` 根下**（分散到专用子目录，脚本实际需要除外）。

## 7. 现象 → 排查速查表

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 游戏能起，`LogOutput.log` 不更新，无 `[DspBridge]` | 加载器/core 代际混装或被覆盖 | `install-game-side.ps1`，再看日志第一行版本 |
| 日志第一行不是 `BepInEx 5.4.17.0` | core 被换成别的版本 | 同上；或 `tools\bepinex-lib` 与 payload 不一致 |
| `-Mode up` 超时，进程还在 | 桥接没注入（同上）；或 stale runtime.json 指向别的进程 | 查日志；删 stale runtime.json 后重开 |
| 游戏退出后 `runtime.json` 还在 | 1.0.1 之前的插件不删 | 升级到 1.0.2 插件；临时手删 |
| `gameLoaded` 恒 false（明明已进存档） | 1.0.2 前把 `isMenuDemo` 当静态字段读 | 升级插件到 1.0.2（见 §5.7） |
| Start modded 后没有 `[DspBridge]` / 无 runtime.json | profile 覆盖游戏目录，DspBridge 不在 profile | `tools\install-r2modman-profile.ps1` |
| IcarusII 聊天窗无反应 / `!tool` 不执行 | 主菜单、cfg 未开 DebugToolConsole、sidecar 无 --debug-tools、未重启 | 见 §5.8 与 IcarusII 专项文档 §9 |
| 两个 token 混用导致 401 | DspBridge(`%LOCALAPPDATA%`) 与 IcarusII(`%APPDATA%\icarus-ii`) 是两套 | 分别读各自的 runtime.json |
| `/health` 连接被拒 | 游戏没跑/桥接没起/端口被改 | `-Mode status` 看三段信息 |
| `/health` 返回 401 | 没带 Bearer token 或 token 旧 | 重新读 runtime.json |
| `set_pause` 返回 `writes_disabled` | `AllowWrites=false` | `-Mode restart -Writes on`（用完 off） |
| `set_pause` 返回 ok 但 `isPaused` 不变 | 主菜单/无存档 | 正常，进存档再看 |
| 进游戏几秒后退出 | 旧存档缺 mod | 换一致 profile 的存档，或只停主菜单验证 |
| 日志中文乱码 | 插件源码编码（csc 按 ANSI 读 UTF-8） | 确认 csproj `<CodePage>65001</CodePage>` 后重编 |
| 脚本执行报乱码 / `A generic error occurred in GDI+` | .ps1 里有非 ASCII | 脚本改纯 ASCII，图输出到 ASCII 目录 |
| 套件明明通过却返回非零 | stray exit code | 看输出标记 `ALL ... PASSED` |
| MCP 客户端里看不到 `dsp_*` 工具 | 客户端未重启/注册路径失效/stdout 被污染 | 重启客户端；`verify-mcp-live.ps1` 定位 |
| 点击没反应/点到别处 | 进程非 DPI-aware 或窗口没前台 | 用 `dev-loop -Mode click -Foreground`（内部已 DPI-aware） |
| 游戏目录突然变回旧版加载器 | r2modman/Profile 部署覆盖 | 重跑 `install-game-side.ps1`；尽量别用 Start modded |

## 8. 本机专属注意

| 项 | 说明 |
|---|---|
| 显示缩放 | 2560×1600 @ **200%**。任何位置相关的脚本必须 DPI-aware，物理坐标 = 截图坐标 |
| 用户名 | `<user>`（非 ASCII）。路径含中文时：PS 脚本一律 ASCII，用 `$env:LOCALAPPDATA` 等变量拼 |
| 磁盘 | 只有 C 盘（`C:\`）。大产物/日志归档注意空间 |
| 权限 | 游戏在 `C:\Games\`，**不需要管理员**；安装脚本遇到需要提权的操作会提示 |
| 执行策略 | `Restricted`，脚本必须 `-ExecutionPolicy Bypass -File` |
| R2 要求 | 插件必须保持对 BepInEx 5.4.17 的可加载性；升级/换版本前先问"R2 那边有这个版本吗" |
