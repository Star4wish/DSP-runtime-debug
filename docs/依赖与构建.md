# 依赖与构建

本仓库只含**源码与脚本**。编译需要两类引用，全部从**你自己机器**上的安装获取，不随仓库分发。

## 1. 依赖一览

| 依赖 | 用途 | 从哪来 |
|---|---|---|
| .NET SDK 8/9/10 | 构建 `DspMcpBridge`（net10.0）与测试工程 | <https://dotnet.microsoft.com/download> |
| .NET Framework 4.7.2 引用程序集 | 构建 `DspBridge`（net472） | NuGet 包 `Microsoft.NETFramework.ReferenceAssemblies`（首次构建自动还原） |
| 游戏程序集 | `DspBridge` 编译时引用 `Assembly-CSharp`、`UnityEngine*` | 你本机的 `<游戏>\DSPGAME_Data\Managed\*.dll` |
| BepInEx core 程序集 | `DspBridge` 编译时引用 `BepInEx.dll`、`0Harmony.dll` | 你本机的 BepInEx（`<游戏>\BepInEx\core\` 或 r2modman profile 的 `BepInEx\core\`） |
| BepInEx 5.4.x 运行时 | 游戏侧实际加载插件 | BepInEx 官方 / r2modman（建议 5.4.17，与 R2 社区一致） |
| Mono.Cecil（NuGet） | 	ools\metaprobe 读取程序集元数据 | NuGet 包 Mono.Cecil，首次构建自动还原（需联网一次） |
| Doorstop 注入器 | 把 BepInEx 注入 `DSPGAME.exe` | 随 BepInEx 5.4.x 发行包提供 |

## 2. 一条命令补齐引用

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\fetch-refs.ps1
```

- 自动从常见 Steam 路径定位游戏，也可 `-GameDir "<目录>"` 显式指定；
- BepInEx 依次找 `<游戏>\BepInEx`、`%APPDATA%\r2modmanPlus-local\DysonSphereProgram\profiles\*\BepInEx`，
  也可 `-BepInExDir` 指定；
- 结果写到 `tools\refs\` 与 `tools\bepinex-lib\`（都被 `.gitignore` 排除）；
- 已存在时不覆盖，要刷新加 `-Force`；`-WhatIfOnly` 只看计划。

> 为什么不上传这些文件：`tools\refs\` 是**游戏自身的程序集**（含 `Assembly-CSharp.dll`），
> 分享游戏代码违反 DSP 官方与社区约定；BepInEx/Doorstop 是第三方项目，请走其官方渠道，
> 也便于你按玩家侧版本对齐。

## 3. 构建

```powershell
# 一次性：校验引用、写本机配置、编译两个工程、跑离线套件
powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup-machine.ps1 -GameDir "<游戏目录>"

# 只编译并部署插件到游戏目录
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-and-deploy.ps1

# 只编译 MCP server（不部署到游戏目录）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-and-deploy.ps1 -Project DspMcpBridge\DspMcpBridge.csproj
```

`setup-machine.ps1` 会生成 `tools\machine.config.ps1`（本机游戏路径）与 `.mcp.json`
（MCP 客户端注册），两者都已在 `.gitignore` 中，不会误提交。

### 构建产物

| 工程 | 产物 | 目标框架 |
|---|---|---|
| `DspBridge` | `DspBridge\bin\Release\DspBridge.dll`（约 44 KB） | net472 |
| `DspMcpBridge` | `DspMcpBridge\bin\Release\net10.0\DspMcpBridge.dll` | net10.0 |

插件目录里**只能有 `DspBridge.dll` 一个文件**：BepInEx 会加载 `plugins` 下任意深度的 dll，
多放一个第三方依赖就可能与其它 MOD 撞版本。

## 4. 编译选项

`DspBridge.csproj` 支持两个覆盖参数：

```powershell
dotnet build DspBridge\DspBridge.csproj -c Release `
  -p:RefsDir="D:\somewhere\Managed" `
  -p:BepInExLibDir="D:\somewhere\BepInEx\core"
```

另有 `<CodePage>65001</CodePage>`：源码是 UTF-8 无 BOM 且含中文日志文案，不指定会让 csc 按 ANSI 解码，
日志里的中文变成乱码。

## 6. 打便携包（可选）

`tools\pack-portable.ps1` 生成一个自带 SDK、NuGet 缓存与引用的离线分发包（约 1.6 GB，**不要提交到 Git**）。它是维护者工具：需要先把便携 SDK 放进 `tools\dotnet-sdk`、按 `game-side-patch/README.md` 备好游戏侧二进制；`tools\smoke-test-package.ps1` 则用来验证打出来的 zip 在干净目录里能否跑通首次流程。
它用于把整套环境搬到没网/没 SDK 的机器。

## 7. 常见构建问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到 ...\tools\refs\Assembly-CSharp.dll` | 没跑 `fetch-refs.ps1` | 先跑第 2 步 |
| `找不到 ...\tools\bepinex-lib\BepInEx.dll` | 同上，或 BepInEx 装在别处 | `-BepInExDir` 指定 |
| `NU1101` / 还原失败 | 没网且无本地 NuGet 缓存 | 联网还原一次，或用 `tools\pack-portable.ps1` 的离线包 |
| 编译通过但游戏内不加载 | 加载器/core 代际混装 | 见 [`踩坑与排查.md`](踩坑与排查.md) §1 |
| 日志中文乱码 | csc 按 ANSI 读 UTF-8 源码 | 确认 csproj 的 `<CodePage>65001</CodePage>` |
