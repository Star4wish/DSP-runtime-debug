## 0. 速读（给新对话 / 新接手的人）

- **作用**：让外部程序（脚本、MCP 客户端、LLM）在游戏运行时读取 DSP 状态，并可在受控开关下做暂停等写操作。
- **组成**：游戏内插件 `BepInEx\plugins\DspBridge\DspBridge.dll`（只读 HTTP 快照）+ 独立进程 MCP server
  `DspMcpBridge`（把 HTTP 包成 MCP 工具）+ 一组 PowerShell 工具（启停、等就绪、日志、截图点击、自检）。
- **工具包在哪**：`<repo>\`（源码 `DspBridge\`、`DspMcpBridge\`，
  脚本 `tools\`，游戏侧说明 `game-side-patch\`，日志 `logs\`）。
  以下所有命令都在这个目录下执行。
- **日常只有 4 条命令**：

```powershell
cd '<repo>'
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode up        # 启动游戏并等桥接就绪
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-all.ps1 -RequireLive    # 全套验证（7 套件）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode status    # 只看状态
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode down      # 关游戏
```

- **IcarusII（游戏内 AI）**：另一个调试通道，sidecar 在 `127.0.0.1:8765`，含 40+ 游戏工具、uGUI 快照/点击、
  其它插件配置桥；`DebugToolConsole=true` 时输入框可用 `!tool <名字> <JSON>` 直调工具（不耗 token），
  `PermissionLevel=takeover` 时写操作不弹确认。接入与坑见 [`IcarusII-游戏内调试集成.md`](IcarusII-集成.md)。
- **硬性边界**：固定组合 `BepInEx 5.4.17 + Doorstop 3.4.0`。这是**产品要求** —— 最终 MOD 要上传 R2
  （Thunderstore / r2modman），玩家侧运行时就是 5.4.17，本机必须与之同代，否则"本机好了、上传就坏"。
  **不要升级 BepInEx、不要混 Doorstop 4**。游戏一律用 `dev-loop.ps1` 启动（Steam），
  不要用 r2modman 的 Start modded（原因见踩坑文档 §2）。
- **不要载入缺少对应 mod 的旧存档**：会崩在 `DSP Mod Save Pre Load` 并退出游戏。

## 3. 一次性安装 / 部署

先按 [`依赖与构建.md`](依赖与构建.md) 补齐引用（`tools\fetch-refs.ps1`），游戏侧二进制按 [`../game-side-patch/README.md`](../game-side-patch/README.md) 准备。然后按顺序执行：

```powershell
# 0) 进工具包
cd '<repo>'

# 1) 机器适配：校验 SDK/refs/库 → 写 tools\machine.config.ps1/.mcp.json/MCP-REGISTRATION.txt
#    → 编译两工程 → 跑离线套件
powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup-machine.ps1 `
  -GameDir '<game>'
#    期望结尾：MACHINE SETUP COMPLETE

# 2) 游戏侧安装：备份 → 装 Doorstop 3.4.0 + BepInEx 5.4.17 + DspBridge 插件 → 自检
#    本步会删掉残留的 .doorstop_version，并把「旧格式↔新格式」都纠正回来
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-game-side.ps1
#    期望结尾：GAME-SIDE INSTALL COMPLETE；并提示 loader: Doorstop 3.4.0 / core: BepInEx 5.4.17.0

# 2.5) 用 r2modman 启动的机器：把桥接装进 profile（否则 Start modded 会用 profile 覆盖游戏目录、把 DspBridge 删掉）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-r2modman-profile.ps1
#    同时写入：<profile>\BepInEx\plugins\DspBridge\DspBridge.dll
#              <profile>\BepInEx\config\icarus-ii.cfg（DebugToolConsole=true / PermissionLevel=takeover）
#    并镜像到游戏目录，备份到 <profile>\_backup_dspbridge_<时间戳>\
#    期望结尾：PROFILE INSTALL COMPLETE

# 3) 编译并部署插件（只在改了插件代码后需要）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-and-deploy.ps1
#    期望：deployed: DspBridge.dll (44032 bytes，1.0.2.0)

# 4) 启动 + 验证
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode up
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify-live.ps1
```

备份位置：游戏目录下 `_backup_dsp_bridge_<时间戳>\`（加载器三件套 + `BepInEx\core` + 插件目录）。

本机现存备份：
- `_backup_dsp_bridge_20261017_052539`（10/17 装 Doorstop 4 前的原始 Doorstop 3 状态）
- `_backup_dsp_bridge_20261022_140827`（10/22 回滚事故现场）
- `_backup_dsp_bridge_20261025_134526`（10/25 切回 5.4.17+3.4.0 前，即 Doorstop 4 + 5.4.23.5 状态）

## 4. 日常使用：`tools\dev-loop.ps1`

一条命令管启停、等就绪、日志、验证、截图点击。`-Mode` 共 **11 个**：

| Mode | 作用 |
|---|---|
| `status` | 游戏进程 / runtime.json / `/health` / 日志诊断 / 日志尾部，只看不动 |
| `up` | Steam `-applaunch 1366540` 启动，等桥接就绪后归档日志；`-RequireSave` 要求进到存档 |
| `down` | 优雅关闭（发 WM_CLOSE，等 `OnApplicationQuit`，插件删 runtime.json） |
| `restart` | down + up；可 `-Writes on\|off` 同时改 AllowWrites（改 cfg 必须重启才生效） |
| `cycle` | down + up + 跑 `verify-live.ps1`（回归用） |
| `log` | 日志尾部；`-Lines N`、`-Filter DspBridge`、`-Follow`、`-Back 1`（看上一次归档） |
| `verify` | 跑 `tools\verify-live.ps1` 的 14 项实测 |
| `watch` | 守护：定期心跳，游戏掉了自动拉起（`-AutoRestart`、`-IntervalSec`、`-DurationSec`） |
| `shot` | 抓游戏窗口 PNG（`-Out` 路径，默认 `logs\shot-<时间戳>.png`）；PrintWindow 黑帧时加 `-Foreground` |
| `click` | 按物理像素点击（`-X -Y -Button left\|right\|double`） |
| `key` | 发按键（`-Key escape\|enter\|tab\|space\|f1..f12\|up/down/left/right`，或 `-VK 27`，可 `-Repeat`） |

常用参数：`-TimeoutSec`（等就绪，默认 300）、`-GraceSec`（关闭宽限，默认 90）、`-NoArchive`、
`-Writes keep|on|off`、`-Foreground`（先切前台再抓/点）、`-X/-Y/-Button/-Key/-VK/-Repeat/-Out`。

常用组合：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode status
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode log -Lines 200 -Filter DspBridge
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode shot -Foreground
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode click -X 310 -Y 854 -Foreground
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode cycle -RequireSave
```

日志归档命名：`logs\LogOutput-<时间戳>-{ready,final,previous}-pid<pid>.log`。

### 4.1 像素兜底（shot / click / key）的本机实测

- `-Mode shot`：PrintWindow 抓帧成功，2560×1600、**86% 非黑像素**（阈值 2% 以下自动回退桌面拷贝）。
- `-Mode click`：主菜单「设置」在物理坐标 `(310,854)`，点击后 PrintWindow 到 99.6% 非黑 —— 设置页真的打开了；
  再 `-Mode key -VK 27`（ESC）验证可以退回主菜单。
- **缩放**：本机 200% 缩放，进程必须 `SetProcessDPIAware` 才能用物理像素（`dev-loop` 内部已做），
  外部脚本不要直接用未声明 DPI 的坐标。
- 游戏是**无边框全屏 + 光标受限**模式（设置页原话），点击前先 `-Foreground` 把窗口切前台。

## 6. 游戏内 HTTP 接口

- 地址：`http://127.0.0.1:17890`；认证：`Authorization: Bearer <runtime.json 里的 token>`；无 token → `401`。
- 端点：

| 方法与路径 | 说明 |
|---|---|
| `GET /health` | 连通状态：pid、schemaVersion、gameLoaded、snapshotTick、unityVersion |
| `GET /state` · `GET /snapshot` | 最近一次只读快照（后台线程每 30 帧整串替换，主线程不阻塞） |
| `POST /command` | `{"op":"<op>","args":{...}}`，未登记 op 一律拒绝 |

- op 表（`CommandRouter`）：

| op | 级别 | 说明 |
|---|---|---|
| `get_health` | L0 | 健康状态 |
| `get_state` | L0 | 运行时状态 |
| `get_catalog` | L0 | 原型表统计 |
| `get_power` | L0 | 电网信息 |
| `get_planet_power` | L0 | 指定星球电力（`planetId`/`planetIndex`） |
| `list_planets` | L0 | 已实例化星球（分页） |
| `find_items` | L0 | 按名字找物品原型 |
| `get_log_tail` | L0 | 游戏日志尾部（`lines`） |
| `get_audit` | L0 | 审计日志 |
| `set_pause` | L1 | 暂停/继续（`paused`）——**受 `AllowWrites` 保护** |

- `AllowWrites=false`（默认）时写 op 返回 `writes_disabled`，不执行。

## 7. MCP server（`DspMcpBridge`）

启动器 `tools\run-dsp-mcp.cmd`（相对路径、重定向 SDK 环境变量、stdout 只输出 JSON-RPC）。
stdin/stdout 走 MCP，诊断一律 stderr。

**Tools（9 个）**：`dsp_health`、`dsp_get_state`、`dsp_get_catalog`、`dsp_get_planet_power`、
`dsp_list_planets`、`dsp_find_items`、`dsp_tail_log`、`dsp_get_audit`、`dsp_set_pause`（唯一写工具）。

**Resources（4 个，只读）**：`dsp://health`、`dsp://state`、`dsp://catalog`、`dsp://planets`。

注册：本机已有两处注册文件 —— 工作区根 `<workspace>\.mcp.json`（绝对路径，推荐）与
把 `.mcp.json.example` 复制成 `.mcp.json` 并改成你的仓库路径（或 `setup-machine.ps1` 生成）。注册后重启客户端才生效；
工具没出现先跑 `verify-mcp-live.ps1` 定位。

## 8. 配置项（`BepInEx\config\org.yourname.dspbridge.cfg`）

首次启动游戏后自动生成；改完需重启游戏生效（BepInEx 5.4.17 不热重载 cfg）。

| 键 | 默认 | 说明 |
|---|---|---|
| `Port` | `17890` | 监听端口（仅 127.0.0.1） |
| `Token` | 随机 | 首次生成后固定；runtime.json 里同一份 |
| `AllowWrites` | `false` | 是否允许 L1 写 op |
| `SnapshotEveryFrames` | `30` | 快照刷新间隔（帧） |
| `AuditLogToFile` | `true` | 写 op 是否落审计文件 |

## 9. 写权限（L1）

```powershell
# 开关需要重启游戏（配置在启动时读入）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode restart -Writes on
# 此时 runtime.json 中 allowWrites=true，set_pause 会被主线程执行：
#   POST /command {"op":"set_pause","args":{"paused":true}}  -> {"schemaVersion":1,"requested":true,"isPaused":false}
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode restart -Writes off   # 用完立刻恢复
```

（主菜单态 `isPaused` 恒为 `false`，那是游戏状态，不代表写路径失败。）

## 10. 限制与边界

- **版本固定**：`BepInEx 5.4.17 + Doorstop 3.4.0` 是唯一支持组合（产品要上 R2）。Doorstop 4 驱动不了 5.4.17，
  混代静默失败（踩坑 §1）。
- **改配置/加 op 需重启游戏**：插件没有热重载；`Assembly-CSharp` 改不了，只能靠已核实的反射入口读。
- **主菜单无存档数据**：`gameLoaded=false` 时存档类 op 返回空，属正常。
- **不要用 r2modman 的 Start modded 启动**：它会把 profile 文件覆盖进游戏目录，桥接消失（本机没有
  `install-r2modman-profile.ps1`，必须用 r2modman 时见踩坑 §2.1）。
- **不要载入缺 mod 的旧存档**：会崩在 `DSP Mod Save Pre Load` 并退出游戏。
- **IcarusII 的 `takeover` 是"不再询问"**：模型/脚本可在不确认的情况下改存档，只在测试档/沙盒里用；
  切回安全档位：游戏内聊天窗右下角「权限」下拉框 → 受限，或改两份 `icarus-ii.cfg` 的 `PermissionLevel=limited` 后重启。
- **两个通道端口分开**：DspBridge `17890`（只读 HTTP）、IcarusII sidecar `8765`（WS+HTTP），互不冲突但都要各自检查存活。
- 像素兜底是最后手段：先 `shot` 看坐标，再 `click`；窗口最小化/黑帧时加 `-Foreground`。

## 11. 维护与同步

- 改了 `DspBridge` 源码：`build-and-deploy.ps1` 编译 → 部署到游戏 → 把新 `DspBridge.dll` 同步到
  `game-side-patch\BepInEx\plugins\DspBridge\`（否则 `install-game-side.ps1` 装回旧插件）。
- 想把整套环境搬到离线机器：用 `pack-portable.ps1` 打便携包（含 SDK/NuGet/引用，约 1.6 GB）。
- 改了加载器/core payload：重跑 `install-game-side.ps1`。
- 换机器：删掉旧 `tools\machine.config.ps1` 后按 §3 重新执行。
- 用 r2modman 装/更新过 MOD 后：`-Mode status` + 日志首行应仍是 `BepInEx 5.4.17.0`，且无 `.doorstop_version`；
  不对就重跑 `install-game-side.ps1`（r2modman 会覆盖游戏根目录，见踩坑 §2.1）。

## 14. IcarusII 游戏内 AI / 工具通道

完整说明（架构、`!tool` 与 AI 两条路径、权限放行语义、实测证据、坑）见
[`IcarusII-游戏内调试集成.md`](IcarusII-集成.md)。这里只列最常用的：

```powershell
# 一次性：把 DspBridge 装进 r2modman profile，并打开 IcarusII 调试直调 + takeover
#         （同时镜像到游戏目录；改完需重启游戏生效）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-r2modman-profile.ps1

# 日常：状态 / 截图 / 发 !tool / 发 AI 提示词
powershell -NoProfile -ExecutionPolicy Bypass -File tools\icarus-ctl.ps1 -Mode status
powershell -NoProfile -ExecutionPolicy Bypass -File tools\icarus-ctl.ps1 -Mode tool -Name game_get_progress -ArgsJson "{}"
powershell -NoProfile -ExecutionPolicy Bypass -File tools\icarus-ctl.ps1 -Mode talk -Text "报告当前星球电力供需"
```

- `!tool` 需要 `DebugToolConsole=true`（安装器会写）；写操作在 `takeover` 下自动放行。
- 聊天窗是开关，已打开时用 `-ChatAlreadyOpen`；JSON 参数建议用 `-ArgsFile` 避免命令行吞引号。
- 外部程序（WS 客户端）只能聊天，**不能**执行 `game_*` 工具——执行必须走游戏内插件。
